# White Box — 自己実行管理システム（Phase 1 / MVP）

自分との約束を、現実の行動と成果までつなぐための実行基盤。
Windows のデスクトップアプリ（Electron + React + TypeScript）。データは完全にこの PC の中だけにある。

## 動かす

```bash
npm install
npm start
```

`npm start` はビルドしてからアプリを起動する。開発中に UI をいじりながら見たいときは：

```bash
npm run dev:app
```

## アプリとして入れる（デスクトップ・タスクバー）

```bash
npm run pack
powershell -ExecutionPolicy Bypass -File scripts\make-shortcuts.ps1 -Exe "release\White Box\White Box.exe"
```

`release\White Box\White Box.exe` が出来て、**デスクトップとスタートメニューにショートカットが置かれる**。
タスクバーに常駐させるときは、スタートメニューの「White Box」を右クリック →「タスクバーにピン留めする」。

アイコンを描き直したら `npm run icons`（`assets/` の PNG と ICO を作り直してから `npm run pack`）。

インストーラ（`.exe` のセットアップ + アンインストーラ）が欲しくなったら `npm run dist`。
ただし electron-builder は `winCodeSign` の展開でシンボリックリンクを作るため、**Windows の開発者モードを有効にするか管理者で実行する**必要がある。
`npm run pack` はその権限を要らなくするために自前で組んでいる（コピーと `rcedit` だけ）。

## 一日の流れ

```
PC を使い始める
  → Welcome（今日やると決めていること・止まっている重要タスク・今日どうするかの余白）
  → Ctrl + Alt + S でタスクを選んで開始
  → 作業（一時停止・再開・タスク切替は同じショートカット / HUD / 現在の仕事から）
  → 50 分で満了ポップアップ（終了 / +15分続ける / 次のタスクへ）
  → 終了レビューで「どこまで進んだか」だけ確認
  → 今日タブで、実際に何にどれだけ使ったかを見る
```

## ショートカット（設定で変えられる）

| キー | 動き |
| --- | --- |
| `Ctrl + Alt + S` | 何も動いていなければ開始画面。実行中なら一時停止。停止中なら**確認なしで即再開** |
| `Ctrl + Alt + W` | 現在の仕事（今のタスク・ほかのタスク・分解・切替） |
| `Ctrl + Alt + D` | メイン画面 |
| `Ctrl + 1..4` | メイン画面の中でタブ切替（今日 / ボード / 記録 / 設定） |

## 画面

| 画面 | できること |
| --- | --- |
| **今日** | 記録した総作業時間、一日の帯（何時に何をやったか）、セッション一覧。行を開くとイベントログ・記録の修正・削除 |
| **ボード** | Inbox / Todo / Doing / Done のかんばん。ドラッグで移動、任意の入れ子（Task Tree）、進捗、プロジェクト絞り込み |
| **記録** | 日ごとの合計と全セッション。過去の記録の修正・削除もここから |
| **設定** | ショートカット、既定のセッション長、自動一時停止、一日の境目、停滞の日数、プロジェクト、書き出し／読み込み |
| **開始**（最前面） | タスクを探して選ぶ／その場で新しいタスクを作って開始。長さは 25 / 50 / 90 / 任意 |
| **HUD**（最前面・小） | 残り時間の輪、今のタスク、一時停止・終了。× で閉じても計測は続く |
| **満了**（最前面） | 終了 / +N分続ける / 次のタスクへ |
| **レビュー** | 実作業・停止・タスクごとの時間、進捗の更新、そのセッション中に生まれたタスクの整理 |
| **現在の仕事**（最前面） | 今のタスクの分解、ほかのタスクへの切替、思いついた仕事の追加 |

## 記録の考え方

- **実作業時間 = 経過時間 − 一時停止の重なり**。スリープ・画面ロックでも自動的に止まる（設定で切れる）。
- **同じ瞬間に前面のタスクは 1 つ**。セッション中に切り替えると区間（segment）として時刻ごと残る。
- **1 セッション = 1 タスク**でも、**途中で切り替える**でもよい。どちらも強制しない。
- 進捗（0〜100%）は**人間が宣言する値**。子タスクや実績時間から自動計算しない。
- アプリが落ちても、最後に記録が取れた時刻でセッションを閉じられる（起動時に選ぶ）。PC が止まっていた時間は実作業に入らない。

## データ

- 保存先: `%APPDATA%\white-box\data\data.json`（設定 → データ → 「保存先を開く」で開ける）
- 保存は一時ファイル経由の置き換え。途中で落ちても本体は壊れない。
- `backups/` に日ごとのコピーを 30 日ぶん保持。
- 設定から JSON で書き出し／読み込みができる。PC を移すときはこれを使う。

## Phase 1 に**入れていない**もの

仕様書どおり、MVP はここで止めて日常投入する。以下は意図的に未実装：

- Today の Project 別集計、Week View、作業時間の推移（Phase 2）
- Blocked / Dependency / Slack / Estimated Effort / Aging / Warning Escalation（Phase 2）
- Weekly Time Budget、Fixed Work（Phase 2）
- Outcome / Success Criteria / Planning（Phase 3）
- Habit / Rest Day / Special Sprint（Phase 4）
- Artifact / Personal History / Gamification（Phase 5）
- Social（Phase 6）、Google Calendar・Windows Activity・AI 連携（Phase 7）

停滞タスクの浮上だけは、仕様の中心思想（「重要と言いながら永遠に何もしない状態を許さない」）に直結するので Welcome に入れてある。

## 開発

```bash
npm test          # セッションの時間計算（純関数）の単体テスト
npm run typecheck # レンダラとメインプロセスの型検査
node scripts/e2e.mjs                       # 実アプリを起動して IPC 経由で通し確認
node scripts/seed-demo.mjs .demo           # 動作確認用データを書き出す
electron scripts/shoot.cjs .demo <出力先>  # 全画面のスクリーンショットを撮る
```

## 構成

```
electron/     メインプロセス（セッションの真実・タイマー・ウィンドウ・ショートカット・保存）
shared/       型と時間計算（メイン／レンダラ双方から使う純関数。テスト対象）
src/          レンダラ（React）。routes/ がウィンドウ、views/ がメイン画面の中身
scripts/      アイコン生成・デモデータ・撮影台・通し確認
```

タイマーはメインプロセスが持つ。ウィンドウを全部閉じても計測は続く。
