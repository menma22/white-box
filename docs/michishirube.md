# 道標の統合

道標の目標マップ・タスク・問題／問い／改善・構造変更の履歴を、White Box へ統合する。目標は「道標」、タスクは「ボード」、気づきは「問題・改善」に入口を分け、目標から実行と記録までつなげる。

「成果」の項目追加は今回の対象外。目標の達成判定や Outcome の設計も含めない。

## 操作と移植元の対応

| 元の道標の機能 | White Box での操作・保存 |
| --- | --- |
| 最上位目標（ヘッド）を複数作成・切替 | 「道標」の最上位目標一覧。開閉状態と選択を保存 |
| 子目標の追加、目標文と理由の編集 | マップの「＋」と目標詳細。入力をその都度保存 |
| 常時自動レイアウト | 葉を縦に並べ、親を最初と最後の子の中点に置く。ノードの手動移動はしない |
| キャンバス移動・拡大縮小 | 背景ドラッグ、ホイール、拡大／縮小、100%、全体表示 |
| 省略された目標・理由の全文 | 拡大率に依存しないツールチップと目標詳細 |
| 複数ヘッドの統合 | 最上位目標を選び、新しい上位目標の子にする |
| 1本の木を上へ伸ばす | 詳細の「目標の操作 → この上に上位目標を作る」。元のヘッドを子にする |
| 枝を隠す・理由を残す | 確認画面で任意の理由を入力。子孫も非表示になるが、親子関係とデータは残る |
| 隠した枝の表示と復元 | 「隠した枝も表示」で破線の枝を表示。「表示に戻す」で隠された祖先も戻す |
| Delete / Escape | Delete は削除せず非表示の確認。Escape はダイアログ・選択・統合操作を閉じる |
| タスクの追加・編集・優先度・締切・完了・削除 | 「ボード → 一覧」。完了済みを開閉。削除は確認あり。ボード表示と一覧表示が同じ Task を変更 |
| 全体／ノード別の問題・問い・改善 | 「問題・改善」と目標詳細から作成・本文／種別編集・解決・削除。解決済みを開閉 |
| 問題から該当目標へ移動 | 目標リンクを押す。隠された枝でも表示モードを切り替えて移動 |
| 構造の履歴 | 目標追加、統合、上位化、非表示、復元を記録。時刻・分岐元・非表示理由と対象への移動 |
| テキスト編集は履歴に含めない | 編集のたびに構造履歴を増やさない |
| ブラウザ内の永続保存 | Electron のメインプロセスが `data.json` に保存。全ウィンドウへ配信し、既存バックアップ・書き出しに含める |

元の背景・ガラス装飾は White Box のクリーム色・緑・既存トークンへ変更する。既存の Ctrl+1〜4 は維持し、道標を Ctrl+5、問題・改善を Ctrl+6 に割り当てる。

道標の中に独立したタスク一覧を重ねない。問題・改善はサイドバーから直接開ける。構造の履歴は道標内に置き、セッションの「記録」と区別する。マップの主操作は「目標を追加」と子目標の追加。取り込みは「その他」、上位化・非表示は「目標の操作」にまとめ、詳細内の問題とタスクは必要なときに開く。

## タスクと目標の関係

目標の木とタスクの親子関係は別に持つ。目標の詳細からタスクを追加すると `Task.goalNodeId` がその目標を指し、通常のボード・開始画面でも同じタスクを扱える。タスク詳細の「目標（道標）」で後から関連を変更できる。

締切は `Task.due` の `YYYY-MM-DD`（日付のみ）として保持する。元の優先度 `mid` は White Box の `normal`、未完了は `todo`、完了は `done` に変換する。移植元はタスクとノードの関連を持たないため、取り込んだタスクの関連は空のままにする。

一覧でタスクを削除すると、ボード表示からも削除される。子タスクがある場合は確認画面に件数を出す。過去のセッションは消さない。

## 元データの取り込み

1. 元データが入っている道標を、普段使っているブラウザとURLで開く。
2. F12 → Console で `copy(localStorage.getItem('michishirube.v1'))` を実行する。
3. White Box の「道標 → その他 → 道標のデータを取り込む」で貼り付ける。JSON ファイルを選んでもよい。
4. 「追加して取り込む」を押す。目標・タスク・問題・履歴の件数を確認する。

元アプリには書き出しUIがないため、上記の読み取りを入口とする。ブラウザの localStorage はブラウザ・URLごとに分離される。違うURLや別ブラウザの空データを取り込まないよう、元画面の内容を先に確認する。

取り込みは既存データへの追加で、元アプリのデータは変更しない。すべてのIDを割り当て直し、ノードの親子関係・問題の関連・構造履歴の参照も同時に変換する。隠した理由・時刻、完了状態、締切、一覧の開閉・非表示表示の設定を保持する。取り込み画面からの操作後はマップへ戻る。現在のデータを置き換える「設定 → 読み込み」とは別の操作。

配列・型・日付・親子関係・参照先・循環を確認し、不正なデータは一部だけ取り込まず拒否する。旧版に存在しなかった追加項目は既定値で補う。同一内容の取り込み済みデータは拒否し、その記録も再起動・White Box の書き出し後に残る。元データの内容を変えた再取り込みは差分同期ではなく、別のコピーの追加になる。

## データの正本と互換性

| 場所 | 責務 |
| --- | --- |
| `shared/types.ts` | GoalMap・GoalNode・GoalIssue・GoalHistory と Task の追加フィールド |
| `shared/goal-map.ts` | 木の参照・可視判定・レイアウトと読み込み検証 |
| `electron/mutations.ts` | 目標と問題の更新、構造履歴の追加、旧データの一括変換 |
| `electron/main.ts` | IPC コマンド受付、保存と全ウィンドウへの配信 |
| `electron/store.ts` | 旧White Boxデータの既定値補完、保存・復元・置換前バックアップ |
| `src/views/GoalMapView.tsx` / `src/views/goals/` | 操作と表示。タイマーや保存の正本は持たない |

既存のバージョン1の White Box データは、道標フィールドがなくても空のマップを補って読める。道標データは既存の `data.json` と日次バックアップに含まれ、「設定 → 書き出し」でまとめて移せる。White Box データ全体を読み込む場合は、検証後・置換前のデータを `backups/before-import-*.json` に保存する。

旧White Boxへ戻すと、その版は新しい道標フィールドを保持しない。戻す必要があるときは、統合版で先にデータ全体を書き出して保管する。

## 検証方法

```sh
npm run typecheck
npm test
npm run build
node scripts/e2e.mjs
node scripts/e2e-goals.mjs
```

単体テストは木の操作・非表示と復元・構造履歴・レイアウト・入力検証・旧形式の変換を検証する。既存の時間計算とタイマーのテストも継続する。

`e2e-goals.mjs` は一時データディレクトリと空きポートで実際の Electron を起動し、本物の IPC・UI操作・保存JSON・再起動後の状態を確かめる。結果と画面画像は `.e2e-goals/` に出力する。スクリーンショットは実際に開いて表示・読みやすさも確認する。

配布版では `npm run pack` 後、PowerShell で `$env:WHITEBOX_EXE = (Resolve-Path 'release/White Box/White Box.exe').Path` を設定し、両方の E2E を実行する。ソース版へ戻すときは `Remove-Item Env:WHITEBOX_EXE` で指定を解除する。
