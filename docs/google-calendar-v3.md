# Googleカレンダー連携の設定 v3

版: v3 / 2026-10-14。前版: [v2](google-calendar-v2.md)。配布元が用意したGoogle OAuthクライアントで接続できるようにし、通常の初回設定からClient ID・Client secret入力を省いた。v1・v2は旧手順として保持する。

## 初回接続

Googleアカウントへのアクセス許可は、自分のブラウザで行う。GoogleのパスワードをWhite Boxへ入力する必要はない。

1. White Boxの **設定 → Google カレンダー** で **Google に接続** を押す。
2. ブラウザで使いたいGoogleアカウントを選び、カレンダーへのアクセスを許可する。認証後はWhite Boxへ戻る。待機をやめるときは **ログインを中止** を押す。
3. **表示するカレンダー** で対象を選ぶ。Googleへの予定追加は、書込権限のあるカレンダーへ保存する。

Client IDとClient secretの入力は通常不要。以前に自分のOAuthクライアントで接続した端末は、その保存済み接続を引き続き使う。自分のクライアントへ切り替える場合だけ、未接続時の **詳細設定（自分の OAuth クライアントを使う）** を開く。

「この配布版には Google 接続設定がありません」と表示される場合、その配布物にはアプリ用の接続設定がない。配布元が設定を同梱した版を用意する必要がある。

必要なアクセス範囲は、アカウントの表示、購読カレンダー一覧の読取、予定の読取・作成。Google側の権限画面は予定の編集・削除も含む表現になるが、この機能は既存のGoogle予定を編集・削除しない。[Googleのアクセス範囲一覧](https://developers.google.com/workspace/calendar/api/auth)

## 日々の使い方

週画面と今日のGoogle予定欄に、時刻付き・終日・繰返しの予定が表示される。Google予定は作業の実績時間へ加算しない。追加するときは **Google に予定をつくる** から保存先・タイトル・開始・終了を指定し、**Google に保存** を押す。繰返し・終日の新規登録はGoogle側で行う。

アプリ起動中は約3分ごと、表示期間の変更時、スリープからの復帰時に取得する。**再同期** でも更新できる。取得対象は最後に表示した期間で、全履歴を端末へ複製する機能ではない。

通信に失敗した場合、その起動中に取得した予定を残し、最終同期とエラーを表示する。取得済み予定はメモリ内に保持するため、終了後には残らない。次の起動時に再取得する。アプリ終了中の同期は停止する。

保存時の通信が途切れると、Google側には作成済みの場合がある。入力を残した **同じ予定を再試行** で結果を確認できる。同じ入力の再試行は同じ予定IDを使う。入力を破棄して別の予定として作り直すと、重複する可能性がある。

**この端末の接続を解除** はWhite Box側の接続を停止する。Googleの予定は消えない。Googleアカウント側の許可も取り消す場合は、[Googleアカウントの接続管理](https://myaccount.google.com/connections)からこの連携用クライアントのアクセスを解除する。

接続後のユーザー別接続設定と更新トークンはOSの資格情報保護を使って暗号化し、通常の作業記録DBとは別に保存する。配布元のOAuthクライアント識別情報はアプリへ同梱するが、ユーザーのアクセストークン・更新トークンを同梱しない。アプリの起動だけではユーザー別の資格情報ファイルを作らない。画面には保存済みの秘密情報を戻さない。OSの安全な保存機能を使えない場合は接続設定を保存しない。

## 接続できないとき

- 認証が許可されない場合は、ブラウザ側でのキャンセル、使っているアカウント、Audienceのテストユーザー設定を確認する。
- `redirect_uri_mismatch` がブラウザに表示された場合は、Desktop app用のクライアントであることを確認する。認証にはアプリがその都度起動するloopbackのポートを使う。
- 権限不足・API無効の場合は、Google Calendar APIが有効か、認証時に予定への許可を与えたかを確認する。
- 更新許可が失効した場合は、接続を解除して **Google に接続** から再認証する。**外部向けアプリがTesting状態の場合、今回のCalendar権限を含む更新トークンは7日で失効する**。長期運用する場合はGoogle側のAudienceと公開・検証条件を確認する。Productionへの変更だけで全アプリの検証要件がなくなるわけではない。[GoogleのAudience仕様](https://support.google.com/cloud/answer/15549945?hl=en)

ローカル認証の方式と前提は、[GoogleのデスクトップOAuth仕様](https://developers.google.com/identity/protocols/oauth2/native-app)を参照。

## 配布元・開発者の設定

配布元はGoogle CloudでGoogle Calendar APIを有効にし、Google Auth Platformにアプリ名・Audience・必要なアクセス範囲を設定する。OAuthクライアントの種類は **Desktop app** とする。External / Testingで使う場合は対象アカウントをテストユーザーへ追加する。公開状態や検証要件はGoogle側で満たす必要があり、クライアントJSONの同梱だけでは完了しない。

非公開のJSONには次の2フィールドだけを入れる。GoogleからダウンロードしたJSON全体ではなく、この形式へ変換する。ユーザーのトークンやアカウント情報は入れない。ダミー値の配布はしない。

- `clientId`: Desktop OAuthクライアントのID（末尾は `.apps.googleusercontent.com`）。
- `clientSecret`: 同じクライアントのClient secret。

PowerShellで非公開ファイルのパスを指定してビルドする。JSON内容をコマンド引数やログへ出す必要はない。

```powershell
$env:WHITEBOX_GOOGLE_OAUTH_CONFIG = 'C:\private\white-box-google-client.json'
pnpm run pack
```

`pack`はサイズ・形式・余分なフィールドを検証し、配布物の `resources/app/assets/google-oauth-client.json` にクライアント設定だけを保存する。既存のアイコンなどのassetsも引き続き同梱する。指定したファイルがない・不正・トークンが混入している場合は、既存の配布物を組み直す前に失敗する。指定を省いた場合は `assets/google-oauth-client.json` を使う。このファイルはGit管理から除外されている。どちらもない場合、接続設定なしの配布物として警告を出す。

ソース起動も同じ環境変数を使える。配布版の起動時には環境変数を使わず、同梱のassetsを使う。既存ユーザーの暗号化プロファイルは同梱設定より優先される。読み込めない既存プロファイルを新規接続で上書きしない。

`invalid_client` はアプリのクライアント設定、`invalid_grant` は接続許可の失効、HTTP 403はアクセス拒否として表示する。Googleが返したURL・説明文・資格情報はエラーに表示しない。形式検査や模擬OAuthのテストは、実際のGoogleアカウントでログイン・予定追加が成功したことの代わりにはならない。
