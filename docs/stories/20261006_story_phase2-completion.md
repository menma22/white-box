# Phase 2 の残項目と終了処理を仕上げる

## 目的

`product-spec.md` §24 の Phase 2 に残る Weekly Time Budgets、Fixed Work、Project Priority、構造化 Task Notes を実装し、利用者が必要な場面で設定・再開できるようにする。既存の実績表示・Task・Session・Note を保持し、入力や保存失敗により文脈が失われないことを確かめる。あわせて、終了中に新しい窓や作業が始まる問題と保存失敗時の終了を防ぐ。

## 受け入れ基準

- [x] Week は実績を先に表示し、必要なときだけ週予算を開ける。睡眠・食事・固定時間の未設定値を推測で埋めない。
- [x] 週予算の下限・上限・範囲・制限なしを保存・再利用でき、生活時間と外部固定予定を控除した配分可能時間と不足を表示する。
- [x] Fixed Work を既存 Task に開始前に登録・変更・取消できる。外部の理由を必須とし、予定登録だけでは Session や作業開始が発生しない。
- [x] 固定予定の週境界・重複を正しく扱い、Today/Week から確認できる。
- [x] Project Priority を Task Priority と独立して変更でき、旧データの未設定を保持する。
- [x] Task の既存 Notes と linked Note を保持し、Problems・Decisions・Next Context を必要な箇所だけ編集できる。作業の開始・再開時に Next Context を参照できる。
- [x] Task/タブの移動・開始・終了・編集を閉じる際に文脈入力を保存する。保存失敗では入力を保持し、移動を止める。週予算の下書きもタブや週の移動で失われない。
- [x] 旧 DB の読み込み・保存・再起動・strict import に互換性があり、保存失敗ではメモリと既存ファイルを復元する。
- [x] 終了の保存が失敗した場合は終了を取り消し、作業を続けられる。終了中は満了・復元・ticker・窓生成を再開しない。
- [x] トレイ・別の窓・native close・アプリ終了でも編集中の文脈の保存を待ち、失敗時は窓を維持する。待機中の再編集で入力を失わない。
- [x] 未確定の週予算の下書きは、保存済みの計画を変更せず、同じDBの再起動で復元できる。
- [x] 型検査・lint・全テスト・build・Storybook と source/配布版の実 UI を確認し、自然終了・再起動後の保存内容・所有 PID 残存を記録する。

## やらないこと

Phase 3 以降の Outcome、週次レビュー、汎用カレンダー、予定時刻による自動開始、本人の睡眠・食事・優先順位の推定は含めない。未再現の過去の終了停止を、別の欠陥の修正だけで原因解決済みと扱わない。

## 設計メモ

- `core` に週予算・固定予定の純粋な計算を置き、時刻・実績の正本は既存の Session と engine を維持する。
- `contracts` に optional な永続データと strict IPC を追加し、`desktop` の既存の save/rollback を通して更新する。
- `renderer` は Week の開閉部分、Project/Task の詳細、Start/Current Work に文脈に応じて UI を出す。linked Note の保存処理を再利用する。
- 生活・外部固定予定の控除後に配分する予算であり、週全体の実績目標とは区別して画面に表示する。
- 終了の観測は実際のイベント・保存・窓・プロセスを記録する。観測器なしでも自然終了を確認する。
- 外部の終了・切替はrendererへ保存を要求し、送信元とrequest IDが一致した成功応答を待つ。入力を閉じるまで固定し、失敗・無応答時には操作を取り消す。
- 週予算の未確定入力はDBごとのキーでElectron profileのlocalStorageに保持する。確定した計画はDBに保存しexport/importの対象となる。未確定のUI下書きはDB exportには含めない。
- この story は残項目の実装開始後に統合担当が作成した。受け入れ基準の確認と証拠は本ファイルのチェック欄に反映する。
