# AIの実績提案を本人が確認して記録する

## 目的

[AIタスク登録](20261004_story_agent_registration.md) に続き、エージェントが終了セッションの作業内容・完了を推測したとき、根拠付きの提案を本人が確認してから実績へ反映する。[製品仕様の External / AI Integration](../product-spec.md#phase-7--external--ai-integration) にある人間の最終決定を守る。

## 受け入れ基準

- [x] MCPから終了セッションへ既存タスクまたは新規タスク名と根拠を提案できる。
- [x] 提案中はタスクの状態・セッション・時間を変更せず、同じセッションの未確認提案を重複させない。
- [x] 今日の画面で根拠と「確認して記録」「違う」を表示する。設定画面から移っても両操作が見える。
- [x] 本人確認でタスクを割り当て、完了の提案があるときだけタスクを完了する。新規タスクも作成できる。
- [x] 区間が空の未割当記録へは開始・終了の全範囲を持つ1区間を作る。開始・終了・一時停止・申告除外・メモは保持する。
- [x] 却下は提案だけを解決し、タスク・実績・時間を変更しない。確認後の再送も重複反映しない。
- [x] 複数区間の記録と消えた対象への確認は全体を変更せず拒否する。
- [x] 確認・却下結果は保存と再起動後も維持される。外部HTTP/MCPから本人確認を実行できない。

## やらないこと

作業の自動監視・自動完了、複数区間の自動割当、入力検知・ノート・カメラは含めない。タスクなしでのセッション開始や新たな計測方法は別変更とする。

## 設計メモ

contractsの提案・確認2コマンドと保存型、desktopの提案・本人確認ハンドラ、空区間への割当、rendererの提案カード、MCPの提案ツールを追加する。外部へ公開するのは提案まで。Storybookは固定された提案のpropsを受け取る。本番処理を複製しない。

## 検証

空区間を既存タスクへ割り当てる回帰2件は修正前に失敗し、修正後に成功した。完了指定の有無に加え、開始・終了、一時停止、申告除外、メモ、予定時間、集中時間が保持されることを検証した。消えたタスクへの確認と複数区間の確認も、保存全体を変更せず拒否する。

`typecheck`、`lint`、143件の単体テスト、`build`、基本E2E、`pack`が成功した。実際のstdio MCPを使うAI E2Eはソース版・配布EXEで各26項目に成功した。提案中の不変性、本人確認、新規タスクへの割当と完了、却下、再送、再起動後の保持を確認し、どちらもrendererのconsole error・未捕捉例外は0件だった。画面遷移を含む道標の回帰E2Eもソース版で61項目に成功した。

設定・提案・確認後の記録のPNGを両版で取得して実物を確認した。提案カードと両ボタンは表示範囲内にあり、ボタンの高さは30pxだった。配布版の撮影直前状態も3枚とも可視・フォーカスあり、表示領域1240×752pxだった。結果は各隔離実行の `result.json`、PNG、撮影直前の `*-state.json` に残した。

UI検証ではCDPの撮影とフレーム待ちが停止するケースを観測したため、検証ハーネスで対象ページの前面化、背景実行抑制の無効化、`Page.enable`、画面からのPNG取得を指定した。更新した経路で検証が成功したことを確認したが、複数の条件を同時に変更しているため、停止原因を1つには断定していない。実行は共通のUI検証ロックで直列化し、隔離アプリの終了を確認してから解放した。
