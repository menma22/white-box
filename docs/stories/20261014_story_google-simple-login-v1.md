# Googleへの簡単な接続 v1

版: v1 / 2026-10-14。依頼出典は今回のチャット。先行する [Googleカレンダー連携 v1](20261012_story_google-calendar-v1.md) と、マージ済みPR #26の実装を引き継ぐ別の変更。

## 目的

Googleアカウントでログインしてカレンダーを使いたい利用者が、Client IDやClient secretの準備・入力を求められず接続できるようにする。今回の依頼は、通常のGoogleログイン、簡単な連携、Googleカレンダーへの予定追加。これは依頼の要約であり、本人の発言の引用ではない。

既存の [仕様書](../product-spec.md) のWeek ViewとGoogle Calendar連携を拡張する。予定を実作業時間に加算せず、ローカルの作業記録・時間配分を保持する。

## 受け入れ基準

- [ ] 配布元のDesktop OAuthクライアント設定を同梱した新規端末で、手動設定なしに **Google に接続** を押せる。起動だけではユーザーの資格情報ファイルを作らない。
- [ ] 通常の画面でGoogleアカウントへの接続と表示カレンダーの選択ができる。Client ID・Client secretは折りたたんだ詳細設定にある。
- [ ] 保存済みの手動クライアント・アカウント・更新トークン・カレンダー選択を保持する。読込故障時に同梱設定で既存接続を上書きしない。
- [ ] 配布設定はclientId・clientSecretのみで、トークン混入・空値・不正形式を拒否する。非公開設定はGit管理しない。
- [ ] 既存のGoogle予定取得・書込権限の判定・同一予定の再試行による重複防止を保持する。
- [ ] OAuthの無効クライアント・失効した許可・アクセス拒否を、秘密値・URL・Googleの生の説明文を出さずに表示する。
- [ ] 型検査・lint・全テスト・buildと、隔離した配布版の基本E2E・Google E2E・実描画PNGを確認する。模擬Google APIと実アカウントの検証を区別する。
- [ ] 実際のGoogle Desktop OAuthクライアントを配布元が用意し、実アカウントでログイン・予定追加を確認する。未実施のまま利用可能な配布版と報告しない。

## やらないこと

Googleの既存予定の編集・削除、実作業記録のGoogleへの自動アップロード、アプリ利用者管理やクラウドサーバーの追加は含めない。Google Cloudの公開・検証条件はローカルのJSON検査で代替できない。模擬クライアントを本番アプリへ設置しない。

## 設計メモ

- contracts: アプリ用OAuthクライアントのstrictスキーマを追加する。ユーザー別の既存プロファイル契約は維持する。
- desktop: 既存の暗号化プロファイルを優先し、ない場合に同梱assetsからクライアント設定を読む。ソース起動では明示した非公開ファイルを指定できる。認証・PKCE・トークン暗号化・予定作成の処理を引き継ぐ。
- renderer: 通常の接続ボタンを先に示し、任意の手動設定を詳細設定に置く。
- packaging: 同じ読込・検証処理で設定を検査してから配布物を組み直す。模擬設定を使う配布検証は、常用アプリと別の作業用worktreeで行う。

最新版の利用・配布手順は [Googleカレンダー v3](../google-calendar-v3.md)。検証の実施結果は外部の成果物へ保存し、このv1本文は改訂時も保持する。
