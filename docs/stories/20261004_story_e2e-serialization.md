# Windowsの実画面E2Eを直列に実行する

## 目的

複数worktreeの並列検証中に、画面撮影の応答停止を観測した。単独実行でも発生し、並列実行だけが原因とは確定していない。検証対象の取り違えとウィンドウの競合を避けるため、同じWindowsログインセッション内の実画面E2Eを直列に実行する。道標E2Eでは撮影・操作前に画面を前面へ戻し、背景描画の抑制を無効化する。

## 受け入れ条件

- [x] 別のworktreeから同時に呼んでも、E2E本体が重ならない。
- [x] 失敗時にもロックを解放し、非ゼロの終了コードとstderrの全行を返す。
- [x] スクリプト名を検証し、対象worktree・実行ファイルの実在を実行前に確かめる。
- [x] ソース版と配布版の実アプリを検証できる。
- [x] 成功・失敗のどちらでも、対象worktreeの検証プロファイルを持つElectronプロセスが残っていないかを確認する。

## 対象外

型検査・lint・単体テスト・buildの直列化、実行中のアプリの強制終了。

## 設計

PowerShellの名前付きMutexで、E2Eスクリプトの実行全体を囲む。各E2Eの終了処理の後にも、対象worktree内の検証プロファイルを持つElectronのPID消滅を確かめる。残留時は失敗を返し、プロセスを強制終了しない。撮影だけでなく、ウィンドウを開く既存E2Eも同じ入口を使う。

## 検証

型検査・lint・118件の単体テスト・build・packが成功。ソース版と配布版で基本E2E32項目と道標E2E61項目が同じ入口から成功し、renderer例外は0件だった。別々のworktreeにある700msの検証スクリプトを同時に起動し、start/endの実測時刻が重ならないことを確認した。stderrを2行出して終了コード7を返す検証でも両行が出力され、次の実行はロックを取得して終了コード0で終わった。各実アプリ検証の終了後に、対象プロファイルのElectron残存が0件であることを確認した。`rAF`を待つ操作のCDP timeoutは観測したが、フレームが停止した原因は断定していない。
