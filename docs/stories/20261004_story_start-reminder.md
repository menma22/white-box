# 入力が続いたときにセッション開始を思い出す

## 目的

セッションを始め忘れて記録が残らない問題を、本人が選べる開始通知で補助する。[製品仕様](../product-spec.md)の自己実行と記録を支える。

## 受け入れ基準

- [x] 既定でOFF。設定から入力活動の監視をON/OFFでき、通知までの時間を1〜60分に変更できる。
- [x] 入力内容を取得・保存せず、Windowsの押下回数だけを端末内で数える。
- [x] 12回以上の押下と設定時間の両方を満たしたらOS通知し、通知から開始画面を開く。
- [x] 既定の継続時間は3分。60秒を超える無操作で継続時間と回数をリセットし、通知後30分は繰り返さない。
- [x] 実行中・一時停止中・休憩中のセッションがあれば通知しない。
- [x] OFFと終了時に監視の子プロセスを止める。監視エラーではOFFへ戻して保存する。
- [x] 旧DBを読み込め、実Windowsのhelper起動・数値出力・停止と実設定画面を確認する。

## やらないこと

入力文字の記録・キー識別情報の保存や送信・アプリ分類・ノート通知・AI連携・カメラ検知を含めない。通知は作業の自動判定ではなく、本人への開始の確認として表示する。

## 設計メモ

既存のsettings:updateへ2設定を加える。開始通知の判断はappの純関数、Windowsの押下回数集計はinfraの専用helper、設定変更と終了処理は独立したstart-reminder-serviceを通してmainへ接続する。

## 検証

- `pnpm typecheck`、`pnpm lint`、`pnpm test`（130件）、`pnpm build`、`node scripts/e2e.mjs`（32チェック）、`pnpm pack`がすべて成功。
- ソース版と配布版の `node scripts/e2e-start-reminder.mjs` はそれぞれ12チェック成功。旧設定の既定値、実UIからのON/OFF、時間変更、厳密なIPC拒否、保存と再起動、実helperの起動と停止を確認。配布版の基本E2Eも32チェック成功。
- 実Windowsの `node scripts/verify-input-activity.mjs` は5チェック成功。GetAsyncKeyStateを使う本番helperから3つの非負整数サンプルを受け取り、停止後の子プロセス終了を確認。入力文字と生の押下回数は証拠へ保存していない。
- 開始通知のE2Eはrenderer例外・console errorが0件。4回のアプリ終了はいずれも強制終了なしでPID不存在を確認。検証用Electronも0件。
- ON/OFFの設定PNGを実物確認し、ラベル・説明・スイッチ・分数入力に欠けや重なりがないことを確認。
- 12回ちょうどを除外する変異（`>= 12` → `> 12`）では境界テストが1件失敗し、復元後は全130件が成功。

継続時間・無操作リセット・通知間隔・各セッション状態での抑制は純関数テスト、通知表示と開始画面へのクリック導線・監視エラーはサービスの依存を置き換えたテストで確認した。実キーボードを長時間操作して通知を出す試験と、OSトーストの画素確認は行っていない。
