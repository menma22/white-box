# Googleカレンダー連携 v1

版: v1 / 2026-10-12。今回の本人依頼を正本とし、週間カレンダー PR #25 の公開コード `d18e596270410772faacf21e5ebc0d1f0c9d3310` に追従する。

## 目的

Googleカレンダーを別に開かなくても、White Boxの週の予定と1日のタイムラインで予定を確認し、新しい予定をGoogleへ登録できるようにする。既存の作業記録・実績集計を保持する。

本人依頼（2026-10-12、このチャット）: 「Googleカレンダーと同期できるように」「週次のカレンダー」「1日のタイムライン」「予定も入れれる」「Googleアカウントでログイン」「内容を反映するみたいなのは自動で」。

## 受け入れ基準

- [ ] ローカルElectronアプリから通常のブラウザでGoogle認証し、選んだカレンダーを連携できる。OAuthクライアント設定が必要な場合は設定画面・手順から辿れる。
- [ ] 接続後の起動・表示期間変更・定期更新で予定を取得し、手動の再同期も可能。状態・最終同期・失敗が表示される。
- [ ] 週の予定表示と日次タイムラインの両方に、通常・終日・繰返し・日跨ぎの予定が反映される。作業記録ゼロの日でも予定が見える。
- [ ] Googleの予定とWhite Boxの予定・作業記録を見分けられる。予定を実作業時間に加算しない。
- [ ] 書込可能なカレンダーを明示して予定を追加できる。ネットワーク失敗時は入力を保持し、同じ送信の再試行で重複を作らない。
- [ ] 読取失敗時は取得済み表示を保持し、古いデータであることが分かる。接続解除・カレンダー選択変更の後に古い応答が予定を復活させない。
- [ ] 更新トークンとクライアントsecretはOSの暗号化を使い、通常DB・エクスポート・レンダラへの状態配信・ログに含めない。終了時に監視・認証待ち・通信を停止する。
- [ ] 既存の予定・実績・DB保存動作を保持し、契約・同期の異常系・実UIを検証する。実アカウント認証の確認が未実施なら、模擬API検証と明確に区別して報告する。

## 範囲

Google側の既存予定の編集・削除、ローカル予定の一括アップロード、セッションのGoogleへの自動書込、クラウドサーバー・アプリ利用者管理は今回に含めない。Googleアカウントへのアクセス許可は本人がブラウザで行う。

## 設計

- contracts: strictなコマンド引数と公開状態。
- desktop: ブラウザ + loopback + PKCE/stateのOAuth、暗号化された別保存先、取得済み予定、定期取得、書込の重複防止。Google通信と資格情報はメイン側が所有する。
- renderer: 設定の接続導線、週間表示、日次の予定表示、Google向け予定入力。予定の表示を既存の実績計算から分離する。
- 既存PRを直接変更せず、依存ブランチから独立PRで差分を提出する。PR #25の更新があれば最終統合前に再確認する。
