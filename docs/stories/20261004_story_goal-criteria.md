# 目標を具体的な成功条件へつなぐ

## 目的

道標の目標に、数字または観測できる成功条件をカードとして紐づける。抽象的な方向性を保ちながら、何を見れば進捗・成果を判断できるかを明らかにする。[道標の仕様](../michishirube.md)の本人によるアウトカム判定に基づく。

## 受け入れ基準

- [x] 目標詳細で数値条件（目標値・現在値・単位・比較）と観測条件（具体的な状態・証拠・本人の確認）を追加・編集できる。
- [x] 条件がない目標に「成功条件を追加」を表示し、上位の抽象的な目標の作成・保存を妨げない。
- [x] 数値条件の到達、観測条件の本人確認、未測定を区別して表示する。
- [x] 条件の追加・更新・数値到達・本人確認・関連タスク完了だけで目標のアウトカムを変更しない。
- [x] 条件を保存・再読込・書き出し・道標の追加取り込みで保持し、条件がない旧形式も読める。
- [x] 不正な数値、空の単位・条件、重複ID、証拠のない観測確認を拒否し、元データを部分更新しない。
- [x] 画面のAI判定を未接続と明示し、数値到達や本人確認をAIによる判定として表示しない。

## やらないこと

自動的な目標達成、曖昧な目標の作成禁止、AIの疑似判定、外部へのデータ送信は行わない。AI接続はユーザーのプロバイダー・認証・送信範囲の選択がある実装へ委ねる。

## 設計メモ

core の GoalCriterion は数値と観測の判別共用体。parse と到達表示は純関数で、OutcomeRecord と独立する。contracts の strict schema でIPC入力を検証し、desktop の create/update と parseGoalMap で保存・読み込みを保持する。renderer は目標詳細に成功条件カードを追加し、マップに条件不足を表示する。数値・証拠は将来のAIレビューへの入力候補になるが、現在は本人の判断材料として使う。

## 検証

- `pnpm run typecheck`・`pnpm run lint`・`pnpm run test`・`pnpm run build` を通過。単体テスト135件が成功。
- `node scripts/e2e.mjs` と `node scripts/e2e-goals.mjs` を通過。道標E2Eは64項目が成功し、rendererエラーは0件。数値条件の追加・未測定の保持・数値到達表示・目標アウトカムの維持・保存後の再起動を確認。
- 実Electronの成功条件カードと最小画面幅のPNGを目視確認。
- 到達比較を一時的に `>=` から `>` に変えると2件が失敗し、復元後は11件が成功。
- E2Eの終了処理はWindowsで子プロセスのexitイベントが欠ける場合もPIDの消滅で確認し、強制終了なしで終了・再起動できた。
