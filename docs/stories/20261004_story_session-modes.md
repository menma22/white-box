# 仕事に合わせて3つの計測方式を選ぶ

## 目的

[仕様書](../product-spec.md)の「仕事の構造と時間の構造を分離する」とSessionの考え方に沿い、時間を区切る仕事・終わるまで測る仕事・休憩を繰り返す仕事を同じ記録へ保存する。

## 受け入れ基準

- [x] 開始画面と設定でタイマー・ストップウォッチ・ポモドーロを選べる。
- [x] 旧記録と方式省略時は通常タイマーとして扱う。
- [x] ストップウォッチは終了まで経過を測り、満了・超過除外を作らない。
- [x] ポモドーロは正確な作業到達時刻から休憩を始める。既定では手動で次周期を再開する。
- [x] 自動再開を選んでも、通知刻みの遅れを実作業にせず、手動停止・ロック・スリープ・整理・復旧を維持する。
- [x] 作業途中の手動休憩からの再開では周期を繰り上げない。
- [x] HUD・現在の仕事・振り返りは方式に合った時間を表示する。

## やらないこと

タスクなしの開始と振り返りでの作業割当。

## 設計メモ

core型・contractsスキーマ・Exact検査を同期する。方式とポモドーロ設定は省略可能な保存フィールドにし、旧データを維持する。session:startの引数を拡張するが、44コマンドは増やさない。desktopの毎秒判定で休憩・周期を制御し、rendererは結果を表示する。

## 検証

147件のunitテスト、44コマンド契約、typecheck・lint・build・packが成功。ソース版と配布版で既存の基本E2E、および3方式・管理・満了の20項目を確認し、設定・開始・HUD・休憩・振り返りの実画面を目視した。手動停止・ロック・スリープを保つ3テストは判定を外すと失敗し、復元後に成功した。撮影のCDP呼出しに10秒の制限を設け、画面を前面へ出してから撮る。

全PRレビューで、休憩中の異常終了後に自動再開する回帰を修正前のテスト失敗で確認した。長い空白と生存記録欠落は復旧を待ち、短い再起動と手動再開の休憩を維持する追加テストで検証する。
