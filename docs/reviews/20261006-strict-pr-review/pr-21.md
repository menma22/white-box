### 追加設計判断: backup namespaceとexport先

既存backupをexport先に選んだ[合成実ファイルprobe](evidence/pr21-backup-export.json)では、現在のDBは変わらない一方、唯一の取込前snapshotが現在DBの内容で置換された。native保存ダイアログで既存backupを選び上書きを承認する経路を想定した検算であり、勝手に消える自動損失とは区別する。probeのnative dialog応答は偽であり、実native操作を再現したとは主張しない。

その観測と「exportはDBのコピーを持ち出し、アプリ自身の復旧assetsを壊さない」という追加判断から、[DataIO](../../../apps/desktop/src/infra/dataio.ts)はStore所有の `backups` subtreeを、新規名も含めexport先から保護する。realpathとWindows caseの既存判定を使い、directory alias経由も拒否する。稼働DB・runtime・それらの一時file・agent接続fileに加え、読込失敗の退避名も保護する。通常の外部exportと、置換失敗時の既存export保持は継続する。Storeのルートdirectory全体を予約する変更ではない。

pruneが削除してよい集合は、regular fileかつ有効な日付の厳密な `data-YYYY-MM-DD.json` だけである。この生成形式を管理対象として予約する判断と、prefixが似た無関係fileの実削除は区別する。任意のfileが同じ管理名を使った場合まで所有履歴を追う仕組みは追加していない。S13でも、名前衝突時に別名を自動生成する仕様は足さず、既存コピーを排他作成で守り、取込は衝突を返す最小方式を選んだ。
