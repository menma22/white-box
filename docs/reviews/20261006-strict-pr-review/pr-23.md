## 再現した問題: P2 見積保存を待たずに詳細を閉じる

元の `OptionalDurationField` は blur で `void save(...)` を開始し、結果を待つための参照・参加登録を持たない。修正前の結合状態の `TaskDetail.flush()` は文脈編集だけを確認していたため、入力欄を blur させて閉じる・別タスクへ進む・タブ移動する経路で、保存未完了の欄を unmount できた。保存失敗のエラーはすでに消えたコンポーネントへ送られ、本人には成功したように見える。

変更前の TSX を TypeScript でメモリ上に変換し、そのままの callback と遅延した保存 Promise で確認した。実 DOM を操作した測定ではない。

```json
{
  "blurReturnedPromise": false,
  "closeAllowed": true,
  "persistedValue": null,
  "draftOnUnmount": "90",
  "errorUpdateAfterUnmount": [{ "mounted": false, "value": "disk failure" }]
}
```

最小修正は [OptionalDurationDraft](../../../apps/renderer/src/features/task-control/optional-duration-draft.ts) に未保存値・実行中保存を保持し、[OptionalDurationField](../../../apps/renderer/src/features/task-control/OptionalDurationField.tsx) を既存 `useDraftParticipant` へ登録すること。TaskDetail の閉じる・関連タスクへ進む経路も参加者の flush を待つ。失敗・不正値は false を返して入力を保持し、flush 中は欄と単位変更を止める。保存中の状態配信は未保存値を置き換えない。

## 結合状態で追加した確認: P1 同じノートの本文を別画面で上書きする

変更前の `NoteAutosave` をそのままメモリ上で実行し、「Main の未保存本文 → Current の保存済み本文を receive → Main を flush」の順で確認した。`flushAllowed: true`、送信 patch は Main の本文で、Current の保存済み本文が通知なく置き換わった。現物 UI の測定ではない。

必要条件は、同じ項目の競合では自動保存・画面移動を止めて両方の内容を残すこと、異なる項目の編集は保存できること、自分の保存の配信を競合にしないこと、配信と返答の間に別画面の保存が挟まっても古い値へ戻さないこと。最新内容を見て本人が明示的に選ぶまで同じ項目を上書きさせない。

- [notes 契約](../../../packages/contracts/src/notes.ts)・[handler](../../../apps/desktop/src/app/note-handlers.ts)・[domain](../../../apps/desktop/src/domain/note-ops.ts): optional な `expected` で項目ごとの元の値を受け、変更済みなら保存前に拒否する。既存の期待値を省いた呼び出しは保持。

## 結合レビューの追加確認: P2 一覧の既存タイトル入力が保存を待たない

親レビューが TaskDetail のタイトル保存でも同じ未保存入力の消失を確認したため、既存 `GoalTasks.tsx` の一覧タイトルを別途追跡した。この関数は PR #23 の元差分で追加された部分ではなく、結合状態で共有する既存入力の問題。

変更前の `TaskTitle` は `onChange`・`onBlur` から戻り値が void の保存 callback を呼び、保存 Promise を画面移動へ渡さず、参加者としても登録しない。blur 後は保存が失敗して未保存のままでも、届いた保存値で `useEffect` が下書きを置き換える。元 TSX 関数を変換して実行した結果は、`onChangeReturnedPromise: false`、未完了保存の対象入力は `User title draft`、その後の配信で表示は `Title saved in other window` に変わった。保存は未成功だった。Main の実 DOM と native close を操作した測定ではない。

[TaskTitleDraft](../../../apps/renderer/src/features/task-control/task-title-draft.ts) は一覧と親担当の TaskDetail で共有する。`GoalTasks` の保存 callback を Promise に戻し、既存 participant を登録する。flush は実行中保存と追加の入力を待ち、意味のある入力の保存失敗・同じ項目の競合では false を返して入力を保持する。保存中の配信も下書きを置き換えず、外部変更の上書きには本人の明示的な選択を必要とする。送信時の名前を `expectedContext.title` として比較する backend の拡張は親担当。

空欄の扱いは既存動作を保持する。タイトルを空欄や空白だけへ変更した場合は、保存済みの名前へ戻して遷移を許し、空欄を保存しない。保存待ちの間に空欄にした場合も、直前の保存成功を待ってその保存値へ戻す。旧データの空・空白だけのタイトルを編集していない場合は、書き換えも新しい保存も行わず遷移できる。空欄を理由に画面から出られなくする保証は追加しない。

[一覧入力](../../../apps/renderer/src/features/goals/GoalTasks.tsx) と [対象テスト](../../../apps/renderer/tests/task-title-draft.test.ts) を変更・追加。初回7件のあと、親担当が上記の互換動作を復元し、旧タイトル・保存待ち中の空欄を含む最終9件へ更新した。[最終9件の成功要約](evidence/pr21-title-tests.json)を直接確認した。保存待ち/失敗保持、追加文字の順次保存、false の拒否、空欄の復帰とtrim、競合/明示再保存、新しい外部保存の起点保持、未編集の外部変更受信を確認する。

## 最終追加差分: 画面全体を保存完了まで止める

個々の participant の flush を順に待つだけでは、最初の入力欄が保存完了して編集可能になった後、後続の保存待ちの間に再編集できる。すべての入力を確認した時点と実際の画面移動の間に新しい未保存入力が生まれるため、欄単位の保存待ちだけでは画面移動の保証にならない。

親担当の [EditorFlush.run](../../../apps/renderer/src/lib/editor-flush.ts) は保存準備の前から移動操作の完了まで frozen を維持し、同時の移動要求を拒否する。[useEditorFlush / runEditorAction](../../../apps/renderer/src/lib/useEditorFlush.ts) は登録済みの参加者と同じウィンドウのcontrollerを使う。Main のタブ移動、Board の表示・フィルタ・タスク選択、一覧の詳細選択・Done操作・完了一覧の開閉がこの経路を使い、保存が失敗すれば移動しない。Main は `inert` とキー入力の抑止で保存中の再編集を止める。native close/quit の prepare が成功した場合も、backend から release が届くまで frozen を維持する。

[TaskDetail](../../../apps/renderer/src/features/board/TaskDetail.tsx) はタイトル・文脈・登録参加者をすべて待つ同一のflush Promiseを共有し、待機中は詳細全体を `inert` にする。これにより、先に成功した見積・タイトルを後続保存中に再編集してから詳細を閉じる抜けを防ぐ。[EditorFlush のテスト](../../../apps/renderer/tests/editor-flush.test.ts)には後続保存と移動の完了まで停止を維持する条件、二重移動の拒否、保存失敗時の移動取消がある。コードとテスト条件に加え、最終source Planning79条件が実DOMの移動・Current Workのnative close・外部終了要求・保存失敗時の拒否・実quitと再起動を確認した。Priority65条件でも保存失敗後の詳細保持が成功した。個々のタイトル入力の全native失敗経路を別個に実測したという主張ではない。全体staticゲートは成功し、配布版の同数条件も成功し、目視の結果は別に記録する。
